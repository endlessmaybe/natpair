# NATPair Mesh 1.2.0：当前功能与优点

本说明对应 `meshclient.py` 中的 `VERSION='1.2.0-mesh'` 和 1.2.0 Windows 原始发布包。

## 1. 两种房间结构

| 人数 | 全员互连 | MC 星形房间 |
| --- | ---: | ---: |
| 2 人 | 1 对 | 1 条房主连接 |
| 4 人 | 6 对 | 3 条房主连接 |
| 6 人 | 15 对 | 5 条房主连接 |
| 8 人 | 28 对 | 7 条房主连接 |

全员互连适合确实需要成员相互通信的场景。MC 星形模式适合一人运行 Java 世界 / 服务端、其他人加入该房主的场景。

星形只改变 NATPair 的辅助配对与调度。Tailscale 的网络授权仍由 Tailscale 决定。房主不会因此变成任意业务中继；玩家之间没有额外辅助探测。

**优点：** 8 人 MC 房间少处理 21 对辅助关系，更贴近实际游戏通信需求。房主仍是所有星形连接的共同端点，每次集中探测一对；不能将少 75% 关系直接解释为少 75% 等待时间。

## 2. Minecraft Java 专用入口

当前界面提供“MC 星形房间（Tailscale 接入）”，角色分为“房主”和“玩家”。

- 房主填写实际游戏端口，向房间公布自己的 Tailscale 地址与端口。
- 玩家自动使用房主公布的端口；玩家本地输入的端口不决定游戏目标。
- 同一房间不允许两个房主，也不允许混用星形与全员互连。
- 玩家可以先入房等待房主。房主明确退出后，可由新房主加入。
- 下方显示“MC 直连地址”，可复制到 Minecraft Java 的“多人游戏 → 直接连接”。

**优点：** 减少手动交换地址和端口的步骤，也能提前拒绝常见的模式冲突。地址出现说明已知目标，辅助直连是否成功仍看成员表验证状态。

## 3. 自动身份交换与原生路径优先

程序读取本机 Tailscale 地址和节点身份，随房间信息交换，再核对成员对应节点。需要辅助时，再交换 UDP 套接字观测到的公网 IPv4 / 端口。

两类地址作用不同：`100.x` 用于识别和访问 Tailscale 设备；公网 IPv4 / 端口是打洞候选。观测服务器看到的映射不保证就是发往另一位成员时使用的最终映射。

已有 Tailscale IPv6 / IPv4 原生直连，并取得真实数据回应和端点证据时，跳过这一对辅助扫描。

**优点：** 保留已可用路径，减少重复探测；成员不必逐个手填其他人的 Tailscale 地址。它没有新增一套独立 IPv6 打洞引擎。

## 4. 配对调度与持续使用

`MeshPlanner` 排除已完成的成员对，优先安排未尝试或等待较久的对，再挑选成员不冲突的组合。每台电脑同时集中探测一对，因此全员互连的 8 人房间最多可同时安排 4 对。

双方交换并确认本轮准备后开始扫描。默认集中窗口为 120 秒；成功后释放扫描位置，未完成的对继续轮转，保留套接字与扫描进度。只剩一对未连、双方心跳新鲜时，续期原任务，避免不断重新准备。

**优点：** 多人可并行，打通即用，减少无进展的反复重建。当前仍是贪心轮转，没有最优最大匹配或完整的动态时间片优化。

## 5. 成员变化与通道隔离

每对成员独立维护源套接字、会话、认证信息、扫描进度和本地代理。退出重进只替换相关成员对；其他已通通道继续工作。

短暂缺少房间消息，不会直接销毁已认证通道。明确退出按本轮身份处理；旧会话延迟报文不能重新占用房间。停止会等待本轮资源清理，再允许重新加入。

**优点：** 房间变化影响范围更小，问题更容易定位。它不能消除物理网络掉线或上游资源耗尽。

## 6. 三个探测档位

| 档位 | 当前限制 | 用途 |
| --- | --- | --- |
| Bifrost 共存 | 扫描最多 1000 包/秒；新增最多 200 组合/秒；15 秒滚动新增最多 900；近期触达参考预算 2400 / 180 秒 | 默认，主动控制突发与新增占用 |
| 不限额 | 没有固定探测包 / 新增组合软件额度；业务和保活仍优先 | 允许积极扫描的网络 |
| 新增组合 1000/秒 | 同一程序内全机滚动一秒首次成功组合不超过 1000；已有组合重发不扣新增额度 | 只需要限制新增的场景 |

组合定义为“本机 UDP 源端口 × 对方 IPv4 × 对方目标端口”。配额由同一程序的全部成员对共享，不是每对各给一次额度。多个独立 EXE 进程不会共享这一预算。

共存档平滑发送，最多积攒两个扫描发送令牌。业务、认证回包、保活和协调优先，另行处理。1000 是扫描上限，不保证持续发满。

**优点：** 主动减少短时突发和新增映射压力，比只限制名义包速率多一层约束。2400 / 180 秒是保护估计，不是读取到的运营商 NAT 容量 / 生存期，也不包含其他应用的映射。

## 7. 共存保护与预算恢复

预算用满后，保留新候选扫描位置；有效轮次内最多以 20 包/秒复测每对最多 128 个近期有效旧候选，其他记录逐步过期后继续新增。没有有效旧候选时等待预算恢复。

可读到 Bifrost 健康日志时，新健康异常临时将扫描降为最多 250 包/秒、新增 50/秒；新数据通道检查失败还会暂停新增 10 秒。没有新异常时，15 秒后恢复原档位。旧日志不会在启动时当作新故障。

程序只读日志，不发送 Bifrost 控制命令，不重启 Bifrost。日志不可读时，主动限额仍生效，并显示不可读状态。

**优点：** 达到预算后不会丢掉扫描位置，也减少大范围重发对预算恢复的干扰。这是软件内保护，不能保证代理在高负载下永不阻断。

## 8. 加密、认证与证据

协调链路使用共享接入密钥，并按配置核对 TLS 证书 SHA-256 指纹。辅助数据传输采用 AES-GCM、方向独立会话密钥、分片和防重放窗口；每对成员有独立身份与会话。

成员表区分原生直连、外层 UDP 已认证、Tailscale 实际数据已验证，以及等待心跳 / 轮次 / 预算。外层 UDP 成功不会直接被当作整个 Tailscale 路径成功。

首次认证成功自动保存证据。完整导出包含成员概况、各对状态、报文元数据和共存预算原因。通常每对保留最近四段约 4 MiB 的轮转日志，另留首次成功证据；不是无限期保存全部历史包。

**优点：** 排错更有依据，能区分“打洞通了”和“业务已采用该通道”。配置密钥、房间码、地址和导出记录仍需要妥善保管。

## 9. 目前未包含的能力

- Android / iOS / macOS 的独立 NATPair 客户端发布包。
- 独立虚拟网卡 VPN、任意业务中继、绕过 Tailscale 授权。
- 独立公网 TCP 打洞；Java TCP 业务由 Tailscale UDP 隧道承载。
- 最优最大匹配调度、无限队列、保证永不掉线的资源管理。
- 对所有 NAT4 / 运营商组合、8 个不同外网成员长期稳定的保证。

验证范围见 [验证记录](VALIDATION.md)。


## 网络适用条件与风险

移动 Wi-Fi 优先已验证的 IPv6 原生直连；星形房主最好有公网 IPv6；全员两两互联时，此类网络最好不加入 IPv4 辅助打洞。UDP 探测可能暂时影响网络，运营商策略也会影响能否连通。使用前关闭防火墙、杀毒软件和其他代理软件，接入模式所需的 Tailscale 保持运行。完整要求与责任说明见 [网络选择与免责声明](NETWORK_AND_DISCLAIMER.md)。
