# NATPair Mesh 1.2.0 使用说明

## 1. 下载、解压与配置

从 [Releases](https://github.com/endlessmaybe/natpair/releases/latest) 下载 `NATPair-Mesh-v1.2.0-Windows-x64-Public.zip`，完整解压到可写的新目录。

保留 `NATPairMesh.exe`、`config.json` 和整个 `_internal`。运行库与驱动在完整包内，不要只发送 EXE。`driver/` 额外保留驱动许可和对应源码。

公开包的 `config.json` 是模板。使用前向协调服务管理员获取实际配置，或按 [服务部署说明](SERVER_SETUP.md) 自建。关键字段如下：

| 字段 | 填写内容 |
| --- | --- |
| `host` | 协调服务器的实际公网地址 |
| `lab_control_port` | TLS 协调端口 |
| `lab_udp_base` | UDP 映射观测起始端口 |
| `room_udp_port` | 加密 UDP 房间端口 |
| `pin` | 服务器 TLS 证书 DER 内容的 SHA-256，64 位十六进制 |
| `access` | 管理员生成的共享接入密钥，64 位十六进制 |
| `control_tail_host` | 可选的协调服务器 Tailscale 地址；不用时留空 |

模板的域名和全零值无法连接到私人服务。房间成员需要使用相同服务与正确配置；房间码不是 `access` 接入密钥。

## 2. 全员互连

1. 每人先登录同一个已授权的 Tailscale 网络，确认 Tailscale 可用。
2. 以管理员身份启动 `NATPairMesh.exe`。
3. 所有人选择“接入 Tailscale（全员互连）”。
4. 一人生成房间码，分享给其他成员。大家填相同房间码与各自昵称。
5. 点击“加入房间 / 开始”。地址与节点信息会自动交换。
6. 看成员表的连接方式和验证状态。成功的成员对先使用，其余继续探测。

最多 8 人，包含自己。房间只有一人时继续等待，不会因为 30 秒无人加入就结束。

## 3. Minecraft Java 星形房间

**房主：**

1. 启动 Java 服务端，或打开世界并选择“开放到局域网”。
2. 记录实际游戏端口：独立服务端常为 `25565`；局域网世界使用游戏当次显示的端口。
3. 选择“MC 星形房间（Tailscale 接入）”，角色选“房主”，填写实际端口。
4. 生成房间码并加入，把码分享给玩家。

**玩家：**

1. 选择相同 MC 星形模式，角色选“玩家”。
2. 用房主发来的房间码加入。
3. 复制下方显示的 `100.x.x.x:游戏端口`。
4. 在 Minecraft Java 的“多人游戏 → 直接连接”中粘贴并连接。

玩家可先入房等房主。更换房主时，旧房主先明确停止退出，新房主再加入。修改角色 / 游戏端口时先停止，再修改并重进。

同房间只允许一名房主；不能混用全员互连与星形模式。房主需要保持游戏、Tailscale 与 NATPair 运行。

NATPair 不启动游戏，也不自动开放任意游戏端口。服务端需监听允许远程访问的地址，并由房主配置游戏自己的入站许可。

公布游戏地址不代表辅助打洞已成功。辅助还在等待时，可用的 Tailscale 现有直连 / 中继路径仍可承载游戏。

## 4. 仅 UDP 打洞

选择“仅 UDP 打洞（不接入 Tailscale）”。该模式仍需要协调服务配置和共同房间码，但不需要 Tailscale 登录，也不会创建 Tailscale 辅助代理。

它用于打洞观察与验证，不是独立 VPN，也不是 MC 游戏接入。无管理员权限时，程序不能自动添加自己的入站许可。

## 5. 选择探测档位

- 与 Bifrost 共用时，双方优先使用默认 **Bifrost 共存** 档。
- **不限额**允许更积极探测，但路由器、运营商映射和网卡仍有资源限制。
- **新增组合 1000/秒**只限制新增组合；旧组合重发不限额，保护范围与共存档不同。

共存档最高 1000 扫描包/秒，但实际发包会受轮次、业务、预算影响。长期等待预算恢复时，不要反复重启程序来追求“清零”：软件看不到 ISP 仍保留的映射。

参数解释见 [功能与优点](FEATURES.md)。

## 6. 状态怎么读

| 显示 | 含义 |
| --- | --- |
| 原生 IPv6 / IPv4 直连 | 已有真实 Tailscale 数据回应与相应端点，跳过辅助扫描 |
| NATPair UDP 直连 · Tailscale 已验证 | 外层有认证往返，且核实了辅助代理上的 Tailscale 数据 |
| UDP 已验证 · 等待 Tailscale 数据确认 | 外层成功，还未证明业务采用辅助通道 |
| Tailscale 已可用 / 经 DERP，代理待选用 | Tailscale 自己有可用回应，辅助代理证据尚待确认 |
| 等待房间心跳 / 等待轮次 / 双方准备 | 暂时不具备本对集中扫描条件 |
| 业务传输优先，探测让行 | 正在优先处理已有业务 |
| 预算恢复倒计时 | 新增 / 近期组合额度不足，正在等待或有限复测 |

“实发 / 新增（秒）”显示近 10 秒的实际速率。首次 UDP 用时从本轮加入开始计算，包含排队时间。

## 7. 停止与记录

点击停止，等待线程与资源清理完成，再重新加入。某一成员退出重进时，其他已通成员对继续维护。

首次成功证据自动写入程序目录 `packet-logs/`。点击“导出完整记录”生成 `NATPair-Mesh-test.zip`。

导出可能包含公网 / Tailscale 地址、节点信息和会话诊断数据。分享前检查内容，只向可信的排错人员提供。日志会轮转，不能将一次导出当作全部历史报文。

## 8. 常见问题

| 现象 | 先检查 |
| --- | --- |
| 协调服务连接失败 | 配置是否仍为模板；地址、端口、证书指纹与接入密钥是否正确 |
| 成员 Tailscale 地址为空 | 是否登录、服务是否运行、成员是否在同一授权网络 |
| 进房后不发包 | 看具体等待原因；单人、原生直连、等待轮次与预算保护都可能无需扫描 |
| 两名房主无法同房 | 原房主先停止退出，再由另一人选择房主加入 |
| MC 连接不上 | 实际游戏端口、监听地址、游戏防火墙许可、Tailscale 基础可达性 |
| UDP 成功但 Tailscale 未验证 | 保留记录，核对管理员权限、驱动、目标身份与实际数据路径 |
| 共存时代理仍掉线 | 降低探测压力并检查日志；保护预算不等于真实 NAT 容量保证 |

所有成员尽量使用 1.2.0 完整包与兼容协调服务。旧配置不一定支持 MC 星形房间。
